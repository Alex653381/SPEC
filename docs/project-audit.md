## 3. 数据源验证报告是否足以支持下一步

结论：**足以支持在本地私有范围内开始数据库与适配层开发，但不足以支持对外部署或宣称许可合规。**

已覆盖：

- 接口可用性与限流现象：新浪股票/指数/ETF、天天基金净值均实测可用；东方财富 push2 行情通道限流已记录。
- 历史覆盖：每类代表性代码给出了实际最早与最新日期。
- 字段口径：实际返回字段、成交量/成交额单位、指数无成交额的陷阱均有记录。
- 复权口径：股票前复权/后复权/不复权对照验证；腾讯前复权被判定不可用。
- 基金净值日期：明确了净值日期与抓取时间应区分，记录了季末周末占位行。
- 使用许可：AKShare、东方财富、新浪、天天基金的条款均已核验原文，结论为“公开展示/再分发授权未确认”。

仍需进一步验证：

- 全历史“交易日缺口”检测尚未量化；现有脚本只查了重复、周末、OHLC、负值和 NaN。
- 新浪与天天基金接口的请求频率上限、批量抓取时的稳定性尚未做压力测试，现有“稳定性较好”仅基于约 20 次调用的小样本。
- 东方财富 push2 的限流阈值、恢复时间仍属推测（依据是错误文本与一次服务器探测），未做受控实验。
- 天天基金完整净值接口在香港服务器上的间歇空表根因尚未确认，只证明底层数据可达。
- ETF 只验证了不复权原始日线；未评估 ETF 分红是否需要复权处理。

## 6. 风险清单

1. 许可风险：所有候选数据源均未确认可对外提供数据；即使改为私有小范围使用，仍存在再分发边界风险，需用户确认使用边界。
2. 部署风险：服务器无 Docker、无 Swap、约 625MiB 可用内存，未来 Worker + API + 前端需控制资源占用。
3. 数据风险：东方财富通道限流、天天基金净值接口间歇空表，适配层必须有非空校验、重试和缓存降级。
4. 口径风险：指数无成交额字段、腾讯 `amount` 实为成交量、ETF 字段不一致、基金周末占位行，需要统一元数据和入库过滤。
5. 安全风险：尚无认证、HTTPS、密钥管理和备份，任何远程暴露前必须先完成访问控制。
6. 版本风险：`pandas==3.1.0` 较新，后续 FastAPI/APScheduler 等依赖尚未纳入测试。
