# 私有部署与安全边界准备

本文只描述准备原则和检查项，不代表服务已经部署，也不代表访问控制已经实现。

## 1. 默认只监听回环地址

配置默认 `HOST=127.0.0.1`，服务只接受本机访问。不要把默认值改成 `0.0.0.0`。

```powershell
.\.venv\Scripts\python.exe -c "from backend.app.core.config import load_settings; print(load_settings())"
```

启动前确认实际监听地址：

```powershell
netstat -ano | Select-String 'LISTENING' | Select-String '127.0.0.1|0.0.0.0'
```

停止本地服务：在启动服务的终端按 `Ctrl+C`；若使用后台进程，先记录 PID 再结束，不要用删除数据目录代替停止服务。

## 2. 私有模式不等于完成身份认证

`APP_MODE=private` 只表达“不对外公开”的意图。当前代码 `AUTHENTICATION_IMPLEMENTED = False`，没有任何认证能力。在真正向其他设备开放前，必须完成以下任一项：

- 接入 Tailscale/WireGuard 等私有网络，只允许私有网络内的设备访问。
- 在应用前部署经过验证的反向认证代理，如 Caddy/nginx 的 Basic Auth、OAuth 代理或短生命周期的访问令牌。
- 采用其他经过安全评估的认证机制，并在部署前完成认证绕过测试。

以下方式不能作为安全边界：

- 隐藏 URL 或使用非标准端口。
- 依赖域名难以猜测。
- 因为“用户数量少”或“非商业”就认为安全。
- 只要设置 `APP_MODE=private` 就默认用户已通过认证。

## 3. 访问策略

当前只实现策略接口 `backend/app/core/access.py`，不提供认证实现：

- `private`：默认模式，匿名只读请求也不视为安全，需要认证。
- `public`：允许匿名只读，但当前所有数据源公开展示许可未确认，不应启用。
- `read_only`：只能读取数据库缓存。
- `admin`：管理操作，普通访客不得触发。
- `fetch`：外部数据抓取，只属于 Worker，普通访客不得触发。

模式只从环境变量读取，不提供通过查询参数或请求头切换模式的接口。`AppSettings` 是冻结对象，加载后不可修改。

## 4. 文件与目录边界

- 数据库文件、备份文件、日志目录、配置文件和 `.env` 不得放在 Web 静态根目录。
- 生产环境不为访客提供 `.env`、备份文件或数据库文件的下载路径。
- SQLite 数据库建议存放在 `data/`，该目录已被 `.gitignore` 忽略；生产配置和 `.env` 不进入版本库。
- 数据库和日志文件权限应仅允许运行服务的系统用户读写。
- 备份使用 SQLite 在线备份 API，不直接复制 WAL 状态下的主库文件。

## 5. 上线前安全检查

1. 确认 `APP_MODE` 为 `private`，或确认访问控制已实现并验证。
2. 确认 `HOST` 默认或显式为 `127.0.0.1`；需要远程访问时改用私有网络而非直接绑定 `0.0.0.0`。
3. 确认匿名请求不能触发抓取、回补、更新或修改配置。
4. 确认错误响应不泄露密钥、数据库路径、内部堆栈或配置内容。
5. 确认 `.env`、数据库、备份和日志不在 Web 根目录。
6. 部署前重新检查 `docs/data-source-audit.md` 和后续的数据许可审查文档。

## 6. 数据许可边界

- 数据源许可尚未确认；当前不得把未确认授权的真实行情部署给其他人访问。
- 开发和图表联调可以使用合成数据。
- 真实数据适配器必须与业务逻辑解耦，后续接入前重新审查许可。
- 不能把“非商业”“个人学习”“用户数量少”直接等同于已获得展示授权。
