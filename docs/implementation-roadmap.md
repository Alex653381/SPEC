# 实施路线图（私有模式）

版本：v1.0（2026-11-01）

本路线图以“本人及一两位同学私有使用”为目标，默认 `private`。在完成访问控制前，不对公网开放任何入口。原 `DEVELOPMENT_SPEC.md` 的“公开访问”假设将在后续修订规范时同步，本文件优先执行私有模式要求。

## 当前目标与接入顺序

- 当前目标是个人自用研究，不把商业化部署作为近期前提。
- 数据源优先级综合个人使用价值、许可、质量、历史覆盖和维护成本判断，不以“免费”作为唯一标准。
- 暂定接入顺序：场外基金净值优先评估，指数和 ETF 次之，股票日线继续作为已启动的适配器验证候选。
- 该顺序是评估优先级，不代表必须在股票验证前接入基金；每次只接入一种资产类型，验收后再扩展。

## 总原则

- 每个阶段只交付一个可运行、可验收的最小切片。
- 匿名 API 只能读已入库缓存；抓取只由独立 Worker 执行。
- 数据源适配统一使用 `docs/data-source-audit.md` 第 8 节的首选接口和口径。
- 不引入 Redis、消息队列或复杂微服务。

## 阶段 0.5：私有模式配置与安全边界准备（已完成）

范围：

1. 建立 `backend/app/core/config.py`：`APP_MODE` 默认 `private`，`HOST` 默认 `127.0.0.1`，非法值明确报错，生产环境禁止 `public`。
2. 建立 `backend/app/core/access.py` 访问策略：私有模式不等于认证通过；只读/管理/抓取操作分离。
3. 创建 `docs/private-deployment.md`，记录监听地址、认证前置条件、文件边界和上线前检查。

交付物：配置与访问策略模块、`.env.example`、`docs/private-deployment.md`、单元测试。

验收：新增测试通过；默认监听回环地址；私有模式不被误认为已完成认证。

数据许可边界：

- 数据源许可尚未确认，当前不得把未确认授权的真实行情部署给其他人访问。
- 开发和图表联调使用合成数据。
- 真实数据适配器与业务逻辑解耦；接入真实数据前重新检查 `docs/data-source-audit.md`。
- 不把“非商业”“个人学习”“用户数量少”直接视为已获授权。

## 阶段 1B：数据源适配器、资产入库与只读 API

范围：

1. 数据源适配器：新浪股票（前复权日线）、新浪指数、新浪 ETF、天天基金单位净值；调用标准化与校验后落库。
2. 代表性资产入库：按 `docs/data-source-audit.md` 第 8 节清单写入真实历史数据。
3. 只读 API：资产搜索、资产详情、历史行情、健康检查；禁止任何触发抓取的入口。
4. 最小前端：本地只读展示 1 只股票、1 项指数、1 只 ETF、1 只基金的持久化真实数据。

交付物：可运行的最小后端 + 最小前端；真实数据入库后可重复查询。

验收：重启后历史数据仍在；基金不显示虚构 K 线；接口不触发上游抓取；非法参数快速返回明确错误。

## 阶段 3：后台更新与数据质量

范围：

1. 独立 Worker 与市场错峰调度。
2. 增量更新、持久化历史回补队列、任务去重、失败重试与退避。

## 阶段 4：私有部署与安全

范围：

1. 访问控制：按阶段 0.5 选定的方案实现认证或网络限制。

3. `.env` 密钥管理，错误日志不含凭证。
4. 日志轮转、SQLite 备份与恢复（含 WAL 一致性）。
5. 资源限制：查询上限、并发限制、Worker 单实例。

交付物：可私有部署、数据可恢复的服务。

验收：未认证请求无法读取数据或触发抓取；容器/进程重启后数据不丢；备份可按文档恢复。

范围：

1. 代表性资产逐一验收。
2. 低配服务器压力测试，确定批次、查询上限和并发参数。
3. 数据源许可边界最终确认；未确认前保持私有访问。

交付物：验收报告、已知限制、扩展计划。

验收：实际测试数据支撑性能与覆盖声明；许可边界有明确结论。

## 本轮结束后的最小下一步

真实 fetcher 和代表性资产入库必须等待数据许可确认。许可未确认前，继续使用合成数据联调，不调用真实行情接口。

下一阶段优先确认场外基金净值候选数据源的授权边界与 `lsjz` 分页/字段语义，再进入单一资产类型的真实只读验证；股票日线保持现状，作为已启动候选，不提前接入。
